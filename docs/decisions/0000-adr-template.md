# ADR-0000: Decision title

- Status: Proposed
- Date: YYYY-MM-DD
- Related issues: #<number>

## Context

Describe the problem, constraints, and forces that require a decision. Include
the scope of the decision and any assumptions that future implementation work
must preserve.

## Decision

State the chosen approach in enough detail that another contributor can
implement it without reopening the same decision.

## Alternatives considered

List the credible alternatives and explain why each one was not selected. If an
alternative remains appropriate for a different future scope, record that
boundary here.

## Consequences

Describe the benefits, costs, operational effects, security effects, and new
constraints created by the decision.

## Review

New ADRs start with `Proposed` status and are submitted in a pull request. The
pull request must link the relevant issue, include evidence that the decision
was considered, and receive review before the ADR can be changed to `Accepted`.
Use `Superseded` when a later accepted ADR replaces this decision, and link the
replacement ADR.
