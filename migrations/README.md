# Database migrations

MaxTasks uses [golang-migrate](https://github.com/golang-migrate/migrate) to apply
numbered SQL migrations. The migration service is available through the Docker
Compose `tools` profile, so the same command works on a fresh database and on an
existing development database.

## Files

| File | Purpose |
| --- | --- |
| `001_initial_schema.up.sql` | Creates the initial application schema. |
| `001_initial_schema.down.sql` | Reverts the initial schema during local development. |

The initial schema has these relationships:

```text
users (1) ────< task_lists (1) ────< tasks
```

### `users`

Stores one account per email address. `email` is required, cannot be blank, and
is unique without regard to letter case. `id` is a UUID generated by
PostgreSQL. `created_at` and `updated_at` record lifecycle timestamps.

### `task_lists`

Stores the task lists owned by a user. `user_id` references `users(id)` and
cascades on user deletion. List names cannot be blank and are unique per user,
without regard to letter case. The user and update timestamp are indexed for
the list view.

### `tasks`

Stores tasks belonging to a list. `list_id` references `task_lists(id)` and
cascades on list deletion. Titles cannot be blank; notes and due dates are
optional. `completed_at` is `NULL` for an open task and set when it is
completed. `position` is a non-negative ordering value. Tasks are indexed by
list and position, with additional partial indexes for due and open tasks.

The database enforces ownership through the relationship chain:
`tasks.list_id -> task_lists.user_id -> users.id`. API queries must still scope
resources to the authenticated user.

## Apply migrations locally

Start PostgreSQL and apply all pending migrations from the repository root:

```powershell
Copy-Item .env.example .env
# Edit .env and replace POSTGRES_PASSWORD with a local-only value.
docker compose up -d db
docker compose --profile tools run --rm migrate
```

The migration service waits for the database health check and records applied
versions in `schema_migrations`. Running the command again is safe; it reports
that no migrations are pending.

To inspect the resulting tables:

```powershell
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "\\dt"'
```

The `migrate/migrate` image is pinned in `docker-compose.yml` so local runs use
a repeatable migration tool version. Do not put `.env` or real credentials in
the repository.
